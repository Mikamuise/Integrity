## 一、项目概述

### 1.1 项目背景

随着公路工程建设、运营养护及质量监管持续向数字化、智能化方向发展，试验检测机构的业务管理模式正由单一业务系统的信息化应用，逐步转向覆盖委托受理、任务下发、样品流转、数据采集与报告编制全过程的协同管理。各业务环节之间信息与实物的衔接效率，已成为影响检测服务质量与管理水平的重要因素。

浦江网联试验室前期已围绕试验室数字化与人工智能应用开展持续建设，建成智慧试验室平台，形成试验室数字孪生、委托系统、安全管理、化学品管理及资产管理等功能模块，部署门禁与分场所视频监控，并上线智能语音助手“小浦”，为本期建设奠定了平台与数据基础。

在此基础上，本期建设以“扫码委托—任务下发—样品运输—试验数据采集—检测报告生成”的业务主流程为主线，将检测报告自动生成作为核心建设内容，优先保障其资源投入；同时优化委托受理与任务下发流程，建立试验数据的多模态采集与确认机制，并将实时业务数据接入“小浦”，形成从委托受理到报告出具的完整业务链条。样品运输机器人作为已确定的系统配置纳入本方案。

本期建设旨在推动试验室由以系统支撑为主、局部环节联动的运行模式，转向全过程贯通、软硬件协同、进展实时查看与智能化交互的运行模式。

### 1.2 项目现状

经过前期建设，试验室在以下方面已形成可供本期利用的基础：

**在平台建设方面**，已建成智慧试验室平台，集成试验室数字孪生、委托系统、安全管理、化学品管理与资产管理等功能模块。本期新增的功能将在该平台内统一集成。

**在检测业务方面**，委托系统已覆盖委托登记、任务下达、数据录入至报告打印等主要环节，各检测项目已配置计算公式，并具备纸质原始记录智能识别与常规检测报告自动生成能力。本期在此基础上，重点建设试验数据采集与检测报告自动生成之间的无缝衔接。

**在智能交互方面**，“小浦”已能够通过语音完成行业知识问答、检测任务信息查询和部分控制，并与烘箱、软化点仪、针入度仪、延度仪等设备实现初步联动。本期为“小浦”接入实时业务数据，扩展其业务查询与辅助操作能力。

### 1.3 建设目标

本期建设在继承前期成果的基础上，以全过程贯通、软硬件协同、进展实时查看和智能化交互为目标，具体包括以下五个方面。

**第一，贯通委托至报告的业务主流程。** 按照扫码委托、任务下发、样品运输、试验数据采集、检测报告生成的顺序梳理业务流程，使一份委托从受理到报告出具的各环节联动运行。

**第二，实现检测报告自动生成。** 作为本期核心建设内容，依据试验数据与既有计算公式自动完成计算，并按报告模板生成试验报告初稿；桥检报告沿用现有成熟框架，纳入现有功能模块统一使用。

**第三，建立试验数据采集体系。** 采用拍照识别与设备直采相结合的方式采集试验数据，打破设备数据孤岛，随着数据积累持续迭代模型，逐步提高智能化流转水平。

**第四，推动“小浦”桌面智能体的业务化应用。** 为“小浦”接入委托、任务、试验数据与报告等业务数据，使其能够在委托填报、业务查询与报告校核等场景中提供交互服务。

**第五，引入样品智能运输系统。** 采用工业搬运机器人，实现样品在委托前台与试验室之间的自主规范运输。

## 二、总体架构

### 2.1 业务架构

本项目的业务架构由检测业务主流程、平台运行能力和智能交互三部分构成。

| 组成部分    | 建设内容                                   | 作用                     |
| ------- | -------------------------------------- | ---------------------- |
| 检测业务主流程 | 委托受理流程优化；试验任务下发；样品智能运输；试验数据采集；检测报告自动生成 | 贯通从委托受理到报告出具的业务全过程     |
| 平台运行能力  | 委托前台引导屏；试验室信息屏展示                       | 集中呈现试验室运转负荷及当日各项试验任务   |
| 智能交互    | “小浦”桌面智能体业务化应用                         | 为客户、试验人员和管理人员提供统一的交互入口 |
![[Pasted image 20261008070047.png]]

三部分之间的关系如下：检测业务主流程在运行中产生委托、任务、试验数据与报告等业务数据；平台运行能力基于这些数据进行可视化呈现；“小浦”调用数据底层，为不同角色的人员提供查询与辅助服务。

### 2.2 技术架构

项目技术架构按照感知层、网络层、平台层、应用层与交互展示层分层组织。

![[Pasted image 20261008070104.png]]

感知层由终端拍照设备、试验仪器、智能搬运机器人与门禁组成，负责数据采集与实物运行；网络层提供试验室局域网与无线网络覆盖；平台层以智慧试验室平台为核心，在既有系统的基础上建设业务数据中枢，并升级“小浦”智能体；应用层承载委托受理、任务调度、数据采集引擎与报告生成等业务应用；交互展示层面向多维角色提供小程序、引导屏、大屏及桌面端等访问方式。

业务数据中枢汇聚委托、任务、样品与试验数据，统一向“小浦”及各业务应用提供数据服务。大模型能力优先采用按调用量计费的轻量级服务模式。

### 2.3 业务流程

本期业务流程覆盖单份委托从客户提交到报告交付的全过程，依次为扫码委托、任务下发、样品运输、设备数据采集与检测报告生成。各环节由前置节点自动触发流转。

![[Pasted image 20261008070111.png]]

本期生成的报告分为两类：一类是试验室内部完成的常规试验项目试验报告，由试验数据自动计算并按模板生成；另一类是桥检等专项检测报告，纳入成熟的功能模块作为独立分支处理。

## 三、建设内容

### 3.1 委托受理流程优化

委托业务在不改变主体逻辑的前提下，围绕减少客户填报工作量、呈现任务信息以及自动触发后续环节进行流程再造，使委托受理成为全流程数字化的完美起点。

**（1）扫码预委托**
在委托前台设置预委托二维码，客户通过微信小程序即可填报委托单位、工程名称、检测项目等内容。系统会自动带出客户历史填报信息。针对纸质委托单，客户也可直接拍照，由“小浦”智能识别并预填表单。这种模式使得客户到达前台前即可完成信息的结构化填报，有效缩短了现场沟通填写与反复核对的时间。

**（2）当日试验任务展示**
在委托前台新增引导屏，滚动展示当日试验任务信息，包含委托编号、检测项目、试验类型及任务状态。对于次日试验的订单也会依照时间序列进行排期呈现。这不仅方便了客户与试验人员直观了解试验安排，也为管理方提供了任务调度的集中展示窗口。

**（3）任务自动派发**
正式受理完成后，系统会自动生成检测任务并实时推送至对应的责任试验人员。当引入了运输机器人时，系统会向机器人调度平台同步下发派送指令。受理环节与后续检测、运输环节的系统级衔接，省去了人工转录和口头通知，大大减少了流转中的等待耗时。

**（4）委托进度反馈**
检测流转全过程中，系统均支持通过小程序或短信向客户推送进度节点与报告出具通知。客户也可随时在小程序内向“小浦”询问预计完成时间。这种透明的主动反馈机制减少了大量的外部催问电话，显著提升了服务体验。

### 3.2 试验任务下发

本节通过系统指令与试验室显示终端联动，使得试验人员能及时、准确地获取试验工单。

**（1）任务实时通知**
系统派单后，试验人员移动端会立刻弹出工单，包括样品名称、检测项目和计划时间。当样品运达试验室时，系统会再次发起核收提醒。人员随时掌握手头工作，任务响应与执行效率得到保障。

**（2）信息屏动态显示**
各试验室内部署的信息屏会动态显示当前试验室承接的任务信息，人员经身份核验进入时，门禁数据自动匹配任务底表，实现人员进出与对应试验任务的精准绑定管理。

**（3）进门语音提示**
当人员进入试验室时，环境内的“小浦”会以语音播报当前的主要任务、所需样品数及检测依据。试验人员还可语音追问细节要求或规范条文，无需在操作间频繁洗手翻查资料。

### 3.3 样品智能运输系统

本期方案标配采用工业搬运机器人负责前台至试验室之间的样品流转。选用X300B-L 工业搬运机器人，配合门禁联动，实现无接触式的智能配送。该款机器人单台预算为10万元，本期共配置2台，合计20万元。

#### 3.3.1 核心设备与技术参数
X300B-L 采用双轮差速驱动与先进导航算法，能够轻松适应试验室通道与人机混合环境，其具体技术指标如下表：

| ---------- | ------------ |
| 机器人型号      | iBen X300B-L |
| 额定运行速度(空载) | 1.5 m/s      |
| 自重         | 110 kg       |
| 举升高度       | 60 mm        |
| 导航到点精度     | <±20mm, ±2°  |
| 末端定位精度     | <±10mm, ±1°  |
| 驱动方式       | 双轮差速         |
#### 3.3.2 运输作业流程

1. 前台受理生成运单后，调度平台派遣空闲机器人至装载位。
2. 业务员装载样品箱，扫码绑定任务并按下放行指令。
3. 机器人按SLAM导航地图自主规划路线，途经试验室时联动门禁自动开启。
4. 到达指定工位后，系统向对应试验人员发送取件通知。
5. 人员取下样品后，机器人自动返航待命或执行低电量回充。
两台机器人可并行执行任务，在高并发受理时有效避免样品积压。

### 3.4 试验数据采集

试验数据自动化采集是检测报告自动生成的基础。针对试验室各类仪器的不同技术底座，本期抛弃增加设备成本的人工二次Pad录入方案，综合采用“拍照识别引擎”与“多模态接口直采”策略，全面打通数据链路。

**（1）拍照智能识别录入**
针对不具备数据接口的传统老旧设备或仍需手填的卡片，试验人员只需使用手机或现场移动设备对原始表单、设备数显屏进行拍照上传。后台OCR识别引擎即可提取核心数值并写入对应的委托字段中。系统对低置信度数据会标红提示人工确认，经过人工确认的数据会同步流入训练集反哺识别模型，从而在常态化使用中逐步降低人工干预频率，既照顾了现行工作习惯又大幅削减了誊抄录入的差错率。

**（2）串口/网口协议直采**
针对带有RS232/RS485通信串口或TCP/IP以太网接口的设备（如万能试验机、压力机等），系统通过边缘计算网关截获设备的底层通信报文。解析协议后，获取实时的检测曲线与最终荷载数据，将其直接封存至任务数据库中，实现核心设备数据的无感化、自动化秒级采集。

**（3）文件解析与API集成**
对于自带上位机软件且能导出Excel、CSV格式报告的仪器，开发统一定制的数据解析抓取组件，自动读取试验结果文件夹并匹配关键数值；对于支持API开放接口的现代仪器，直接通过HTTP/MQTT等标准接口对接。多样化的直采手段彻底扫清了设备数据孤岛，确保了检测数值的绝对原始性和可追溯性。

### 3.5 检测报告自动生成

作为本期重点建设内容，系统将根据试验数据与模板引擎自动生成排版报告，提高出具效率。

**（1）试验报告自动生成**
试验数据一经直采或确认提交，系统将立即调用既定计算公式模块完成推算，随后匹配现行规范报告模板，一键生成带有数据图表及排版格式的试验报告初稿。报告转入线上流转经试验人员和审核人员签发后推送给客户。该功能先期覆盖业务量最大的常规试验，有效压缩了出具周期，从底层逻辑上杜绝了原始数据与最终报告的不一致现象。

**（2）专项检测报告（桥检报告）**
针对桥梁检测等外业专项报告，考虑到其业务逻辑特殊性，系统沿用其成熟的独立编制框架，并封装为平台的一个专门功能入口，不强制改变其现有作业习惯。这保障了桥检业务能平滑过渡、迅速投入使用而无需高成本的重复开发。

**（3）报告智能辅助校核**
系统不仅负责生成初稿，“小浦”智能体还会在后台静默对报告进行校核。它通过比对直采原始数据与报告结果的逻辑一致性，复核指标是否超出国家标准限值，并向审批人员提示潜在错误风险，为出具高质量检测报告加上了一把智能安全锁。

### 3.6 “小浦”桌面智能体业务化应用

依托业务数据中枢沉淀的全量实时数据，本期以桌面端、移动端智能体的形态，将“小浦”从单纯的问答助手升级为深度参与流转的业务管家。
#### 3.6.1 业务数据与权限接入
为“小浦”开放底层结构化业务数据库查询端口，并严格按照提问人员的账号角色进行权限鉴权过滤。同时，将高频操作封装成插件工具供大模型调用。由此，“小浦”既能理解复杂的上下文指令执行操作，又能确保业务数据的安全红线不被跨越。
#### 3.6.2 信息提取与智能填表
当客户提供各种非标准格式的纸质委托单时，“小浦”可直接调用视觉识别模型提取纸质委托单中的单位、联系人、项目明细等关键信息，并映射到系统的标准表单中。客户只需浏览确认即可提交，填报负担被大幅削减。
#### 3.6.3 多维角色业务查询
通过自然语言交互，可询问“xx沥青样品现在走到哪一步了？什么时候出报告”；试验人员可询问“今天下午还有几批钢筋拉伸要做”；管理人员可询问“调出今天异常超时的试验任务”。智能体能够直接跨系统抓取数据并汇总答复，消灭了人工登录各模块点选报表的繁琐过程。
